# 설계: GitHub Pages 도장판 뷰어 v1

작성일: 2026-07-23
상태: 승인 대기
브랜치: `claude/pn532-nfc-i2c-wiring-o9x7b1`

## 목적

관람객이 NFC 카드(NTAG215)를 스마트폰에 대면 카드에 저장된 URL이 열린다.
이 URL은 GitHub Pages에 호스팅된 정적 페이지를 가리키며, URL 파라미터로 전달된
닉네임·식별번호·방문 전시관 목록을 읽어 **개인화된 도장판 화면**을 그린다.
백엔드 서버가 없다 — 모든 상태는 URL 안에 있다.

이 문서는 그 **뷰어(읽기 전용 화면)** 하나만 다룬다. 발급 스테이션, 도장 리더,
초기화 기능은 별도 스펙에서 다룬다. 셋은 여기서 정의한 데이터 계약을 공유한다.

## 범위

포함:
- URL 파라미터를 읽어 도장판을 그리는 정적 페이지
- 개인 인사, 진행률(도장판), 방문 전시관 목록, 식별번호 표시
- 파라미터 없음·이상값 등 엣지 케이스 처리
- 순수 로직 함수의 단위 테스트

제외 (나중에 논의):
- 완주 축하 화면
- 지도/시각적 배치도
- Supabase 등 서버 연동
- 카드에 쓰기(발급·도장·초기화) — 별도 스펙

## 아키텍처

- **호스팅**: GitHub Pages, 소스 = `main` 브랜치의 `/docs` 폴더.
  사이트 주소 = `https://elderlord.github.io/NFC-stamp/`.
  이 주소가 카드에 굽는 URL의 BASE로 확정된다.
- **빌드 없음**: 번들러·프레임워크·의존성 없음. GitHub Pages에 그대로 배포.
- **파일 구성** (역할 분리):

| 파일 | 역할 | DOM 접근 |
|---|---|---|
| `docs/index.html` | 뼈대 + 스타일(내장 CSS) | — |
| `docs/logic.js` | 순수 함수: 파싱, 진행률 계산, 전시관 설정 | 없음 (테스트 가능) |
| `docs/app.js` | `logic.js`를 import해 화면 렌더링 | 있음 |

`index.html`은 `<script type="module" src="app.js">`로 app.js를 로드하고,
app.js는 `logic.js`를 ES 모듈 import 한다. GitHub Pages는 ES 모듈을 그대로 제공한다.

## 데이터 계약 (뷰어가 읽는 URL)

```
https://elderlord.github.io/NFC-stamp/?n=철수&id=2026-0001&s=1,2
```

| 파라미터 | 의미 | 규칙 |
|---|---|---|
| `n` | 닉네임 | URL 인코딩 문자열(한글 허용). 없으면 익명 인사로 폴백 |
| `id` | 식별번호 | 예 `2026-0001`. 화면 하단에 작게 표시. 없으면 표시 생략 |
| `s` | 방문 전시관 번호 | 쉼표 구분(`1,2`). 없음/빈값 = 0곳. 중복은 1회로, 순서 무관 |

전시관 마스터는 `logic.js` 상단의 설정 객체로 둔다:

```js
export const EXHIBITS = {
  1: { name: "우주관" },
  2: { name: "로봇관" },
};
```

- 총 전시관 수 = `Object.keys(EXHIBITS).length` (지금은 테스트용 2곳).
- 전시관을 늘려도 이 객체만 수정하면 되며 렌더링 로직은 바뀌지 않는다.

## 화면 구조 (모바일 우선, 세로 레이아웃)

1. **인사** — "{닉네임}님, 환영합니다". `n`이 없으면 "환영합니다".
2. **진행률** — "{방문 수} / {총 수} 방문" 텍스트 + 도장판.
   도장판은 전시관마다 원 하나: 방문 = 채운 원(⬤), 미방문 = 빈 원(◯).
3. **방문 목록** — 다녀온 전시관 이름 리스트. 0곳이면 "아직 방문한 전시관이 없어요".
4. **푸터** — "ID: {id}" 작게. `id` 없으면 생략.

## 데이터 흐름

1. 페이지 로드 → `parseParams(location.search)` → `{ n, id, visited: Set<number> }`
2. `computeProgress(visited, EXHIBITS)` →
   `{ done: number, total: number, items: [{ id, name, visited: boolean }] }`
3. `app.js`가 위 결과로 DOM을 구성해 렌더링.

파싱·계산은 전부 `logic.js`의 순수 함수로 두어 DOM 없이 테스트한다.

## 에러 / 엣지 처리

| 상황 | 처리 |
|---|---|
| 파라미터 전혀 없음 (맨 URL 직접 열기) | 플레이스홀더 안내: "카드를 스마트폰에 대면 나의 도장판이 열립니다" |
| `s`에 설정에 없는 번호 (예 `99`) | 무시. 진행률 분자에 포함하지 않음 (오타·미래 확장 대비) |
| `s`에 숫자가 아닌 값 | 무시 |
| 닉네임에 특수문자/스크립트 | `textContent`로만 삽입, `innerHTML` 사용 금지 → XSS 차단 |
| `s`에 중복 번호 (`1,1,2`) | `Set`으로 1회만 처리 |

## 테스트

- 러너: Node 내장 테스트 러너 (`node --test`). 브라우저·의존성 불필요.
- 파일: `test/logic.test.mjs` — `docs/logic.js`를 import해 순수 함수 검증.
- 케이스:
  - 정상 파싱: `?n=철수&id=2026-0001&s=1,2` → `{n:"철수", id:"2026-0001", visited:{1,2}}`
  - `s` 없음 → `visited` 빈 Set
  - 중복·미지 번호 `s=1,1,99` → 파싱은 `visited:{1,99}` (중복만 제거),
    미지 번호 99를 거르는 책임은 `computeProgress`에 있어 진행률 분자엔 미포함
  - 닉네임 URL 인코딩 디코드 확인
  - `computeProgress`: 방문 수/총 수/항목별 visited 플래그 정확성
